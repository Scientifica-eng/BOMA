## Competing acceptance hypotheses

Test four representation-neutral candidate contracts.

### H1 — Field extension only

```text
C is a field with a faithful embedding of R.
```

### H2 — Field extension plus a square root of `-1`

```text
C is a field extension of R
+
∃ I, I² = -1.
```

### H3 — Generated quadratic extension

```text
C is a field extension of R
+
distinguished I with I² = -1
+
every element has a unique expression a + bI, a,b ∈ R.
```

### H4 — H3 plus algebraic closure

```text
H3
+
every nonconstant polynomial over C has a root / equivalent algebraic-closure contract.
```

## Acceptance criterion for this experiment

A suitable Stage-One semantic contract should:

```text
exclude underdetermined larger/smaller extensions;
identify the intended quadratic extension up to a route-neutral isomorphism;
not presuppose a carrier representation;
not silently require mathematical infrastructure unrelated to identifying that extension;
be strong enough to force later construction routes to reconverge at a meaningful interface;
leave additional theorems available as later strengthenings.
```

# DO

## Experiment A — H1 discrimination

Observation:

A field-with-R-embedding contract does not distinguish complex numbers from the accepted real field itself or from many other field extensions.

The identity map already demonstrates that field structure and faithful R embedding alone do not encode the new complex-specific extension.

Result:

```text
H1 = REJECTED AS C ACCEPTANCE SEMANTICS
reason = severe underdetermination
```

This is not a failed construction route; it is a failed **acceptance specification hypothesis** and is retained for Learning Graph value.

## Experiment B — H2 discrimination

Adding a distinguished square root `I²=-1` excludes R itself because an ordered field has no real square equal to `-1`, but it still does not force the whole extension to be generated by `I`.

Any strictly larger field containing a copy of the quadratic extension and the same distinguished root would continue to satisfy H2.

Therefore H2 identifies a **property possessed by C**, but not enough structure to identify the intended C domain at the BOMA acceptance boundary.

Result:

```text
H2 = REJECTED AS COMPLETE ACCEPTANCE SEMANTICS
reason = root existence does not control extension size/generation
```

## Experiment C — H3 adequacy

Under H3, every candidate value has unique coefficients relative to `1` and `I`.

Given two independent candidate realizations:

```text
(C₁, ι₁, I₁)
(C₂, ι₂, I₂)
```

satisfying H3, define the comparison map by the common interface:

```text
Φ(ι₁(a) + ι₁(b) I₁)
  :=
ι₂(a) + ι₂(b) I₂.
```

Coordinate uniqueness makes the map independent of any hidden representation. Generation gives totality/surjectivity of the description. The shared field laws and relation `I²=-1` make addition and multiplication reduce to the same coefficient algebra in both candidates. Reversing the construction supplies the inverse map.

Therefore H3 supports a canonical `R`-algebra/field isomorphism preserving the embedded R and the distinguished generator.

No statement in this comparison requires either candidate carrier to be definitionally:

```text
R × R
polynomial classes
pairs
matrices
```

Result:

```text
H3 = ADEQUATE CORE STAGE-ONE SEMANTICS
```

The later formal proof of the comparison theorem remains an acceptance Claim (`C-CL-COMPARE-001`) and must receive V5 evidence; this experiment establishes the architectural reason for requiring it.

## Experiment D — H4 strengthening test

Algebraic closure is a true and major classical property of the standard complex field, but adding it to the initial carrier-identification contract introduces a qualitatively different obligation:

```text
polynomial infrastructure
root-existence theory
FTA / equivalent real-closedness-scale mathematics
possible additional completeness/analysis dependencies
```

H3 already pins the intended quadratic extension relative to accepted R. Therefore H4 does not improve representation discrimination enough to justify importing this much stronger theorem into the Stage-One acceptance gate.

Result:

```text
H4 = DEFERRED STRENGTHENING
not rejected as mathematics
not required for Stage-One C acceptance
```

No algebraic-closure Claim ID is created merely because the property is standard.

# Observations

1. The main acceptance risk was **under-specification**, not choice of representation.
2. `I²=-1` is necessary for the chosen Stage-One semantics but does not by itself control the carrier.
3. Generation without uniqueness would still allow nontransparent identity/collapse behavior; uniqueness is what turns `a+bI` into a classification theorem rather than notation.
4. The pair notation needed to explain two coefficients does not force a pair carrier.
5. H3 creates a natural future reconvergence invariant: candidate routes can be compared through coefficient preservation even when their raw identities differ.
6. Algebraic closure belongs to a later theorem program unless BOMA explicitly revises the Stage-One objective.
7. Core C algebra appears to need only R's accepted field/order surface, not Dedekind completeness, Q-density, or the Archimedean theorem.
8. The first likely hidden dependency risk is proving that `-1` is not a real square and that a sum of squares is nonzero when the coefficient pair is nonzero. These must be tested against the accepted R Claim surface rather than proved through Dedekind internals.

## 2. What remains a construction choice?

Still completely open:

```text

formal equality regime
normalization strategy
multiplication implementation
inverse construction
proof route for coordinate uniqueness
proof route for comparison isomorphism

```

This validates opening a Decision Point only **after** the semantic contract was stabilized.

## 3. Field behavior: primitive datum or derived theorem?

For a concrete rank-two R-algebra satisfying the intended relation, field inverse behavior can mathematically be proved from the ordered-field structure of R using a denominator such as `a²+b²` or a route-equivalent argument.

The acceptance contract nevertheless requires **certified field behavior** because downstream C should not have to reconstruct this fact from representation internals.

Classification:

```text
field behavior = acceptance-required exported property
specific inverse formula = route-specific supporting construction
```

## 4. `I ∉ R`: primitive datum or derived theorem?

It need not be primitive representation data. It can follow from:

```text
coordinate uniqueness
```

or from:

```text
I²=-1
+
accepted ordered-field consequence that -1 is not a real square.
```

Therefore the non-collapse Claim is marked `DERIVED-REQUIRED` rather than used to define the carrier.

## 5. R completeness is not currently a core C dependency

No step in the H3 identification argument consumes:

```text
Dedekind LUB completeness
Q density
Archimedean natural upper bounds
```

This is scientifically important because the accepted real construction is much stronger than the minimum algebraic input apparently needed to construct C as a quadratic extension.

The conclusion remains provisional at formal-closure level until actual Lean dependency extraction is available.

## 6. The first formal experiment should target the boundary, not a carrier

The most informative next test is not “can pairs implement C?”

It is:

> Can the R-level non-square / sum-of-squares lemmas needed by likely C routes be derived from the **accepted R interface alone**, without reaching Dedekind representation internals?

This became `C-RQ-001` in `BOMA-C-R-DEP-001`.

That experiment can reveal whether the downstream interface is sufficient before any representation selection biases the dependency architecture.

# HiddenAssumptions

The Study identifies assumptions that must not remain hidden:

1. Accepted R is an ordered field strong enough to derive that `-1` is not a square.
2. A concrete inverse proof may need nonnegativity/zero-characterization for sums of squares.
3. The route-neutral comparison theorem assumes both candidates satisfy the same embedding/generator/unique-coordinate contract.
4. Polynomial-route infrastructure is not currently part of accepted R and would be new C-stage machinery.
5. No global real inverse selector is available merely from acceptance; witness-based use or an explicit selector commitment may be needed depending on the route.

All five are now explicit in the acceptance/dependency records.

# LessonsLearned

1. A new number stage can be mis-specified before any code exists; acceptance design itself requires experimental discrimination.
2. “Contains a square root of `-1`” is a property, not enough by itself to classify the intended complex extension.
3. Generation plus uniqueness supplies both semantic precision and a natural representation-reconvergence invariant.
4. A standard theorem about an object need not belong to the minimum contract that identifies the object.
5. The best first downstream experiment after an accepted representation-heavy stage may be a **boundary sufficiency test**, not immediate construction.
6. Claim transparency should begin with unproduced acceptance Claims; this makes later representation-induced dependencies visible as additions rather than invisible defaults.
7. An open Decision Point is more accurate than prematurely turning candidate routes into canonical Blocks.

# E-003 — Conflict / Compatibility

**Cycle:** `PDCA-001`  
**Status:** Experimental / provisional  
**Source record:** `LAB/CONFLICT_COMPATIBILITY_PROBE_001.md`  
**Epistemic status:** `HYPOTHESIS`

## Question

If a Brick need not depend on a previous Brick, what does it mean for it to be admissible alongside previously established commitments?

## Initial hypothesis

A candidate Brick should not introduce a commitment that conflicts with commitments already in scope.

The purpose of this probe is only to establish a minimal distinction between dependency, compatibility, and admissibility. It does not attempt to define a complete consistency theory.

## Minimal commitment model

For the probe, a Brick is represented by a small set of explicit commitments over named propositions:

```text
A: P
B: Q
C: ¬P
```

This is deliberately a toy language. It does not claim that BOMA commitments are reducible to propositions.

## Cases

### Case 1 — Independent and compatible

```text
A: P
B: Q
```

No proposition receives incompatible commitments.

**Result:** compatible in the toy model.

### Case 2 — Independent but conflicting

```text
A: P
B: ¬P
```

Neither Brick depends on the other, but the commitments cannot be jointly adopted under the probe semantics.

**Result:** conflict.

This is the key case: independence does not imply compatibility.

### Case 3 — Dependent and compatible

```text
A: P
C: P → Q
```

C is treated as depending on A for the intended construction context and adds a compatible commitment.

**Result:** compatible in the toy model.

### Case 4 — Dependent and conflicting

```text
A: P
D: ¬P
```

Declaring D as dependent on A does not neutralize the contradiction.

**Result:** conflict.

## Findings

```text
Independence implies compatibility        NO
Independence permits compatibility        YES
Dependency implies compatibility          NO
Dependency and compatibility independent   YES
Minimal non-conflict distinction          SUPPORTED
Full conflict calculus                     OPEN
```

## Consequences for Brickhood

The probe supports this provisional structure:

```text
Brick
├── Identity
├── Commitment
├── Depends_on: 0..n
└── Admissibility condition:
       compatible with commitments in scope
```

A dependency-free Brick can therefore be valid if its commitment is compatible with the existing context. A dependent Brick can be invalid if its new commitment conflicts with that context.

This is not a formal Brick definition.

## Consequences for the DAG model

For:

```text
A ─────┐
       ├──→ C
B ─────┘
```

with `A: P` and `B: Q`, the graph can be structurally represented and the commitments can be jointly admissible under the toy model.

With `A: P` and `B: ¬P`, the same graph remains structurally representable but is not jointly admissible under the probe.

Therefore:

```text
Graph validity
      ≠
Construction admissibility
```

## Distinctions established by the probe

### Dependency validity

Is the declared dependency relation sufficient for the intended meaning?

### Compatibility

Can the commitments coexist in the current context?

### Construction admissibility

May the candidate be introduced at this point without violating the relevant rules?

These may eventually require different mechanisms.

## Important limitation

The toy model uses explicit contradictory commitments. It does **not** define BOMA conflict as syntactic negation and does not establish a complete consistency calculus.

A mature definition may need to address:

```text
axioms
definitions
typing constraints
logical commitments
architectural commitments
```

and may depend on the selected object logic or meta-logic.

## Next question generated by this experiment

Can a Brick be locally checked for compatibility using only its declared context, without requiring global recomputation of the entire construction?

This matters for incremental construction and later machine verification.

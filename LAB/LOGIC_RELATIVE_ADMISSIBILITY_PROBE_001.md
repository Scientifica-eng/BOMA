# Logic-Relative Admissibility Probe 001

**Cycle:** `PDCA-001`  
**Status:** Experimental / provisional  
**Purpose:** test whether Brick admissibility and apparent conflict depend on the logical regime in which commitments are evaluated.

## 1. Trigger

A discussion of non-conflict raised a stronger hypothesis: compatibility cannot necessarily be treated as independent of the logical framework. In particular, an intuitionistic context does not validate every classical principle.

The experiment therefore distinguishes:

```text
contradiction
logical consequence
logical strengthening
unresolved status
```

rather than treating every difference in inferential strength as conflict.

## 2. Logical regimes under comparison

### L-I — Intuitionistic baseline

The default regime for the experiment.

It does not in general validate:

```text
P ∨ ¬P
¬¬P → P
```

### L-C — Classical extension

A regime in which classical principles such as excluded middle and double-negation elimination are available.

### L-I+C — Intuitionistic base plus an explicit classical commitment

This is treated as a transition case: the underlying constructive framework remains visible, but an additional classical principle is explicitly admitted.

This is not presented as a final BOMA taxonomy. It is a probe for separating logical regime from Brick content.

## 3. Candidate Brick commitments

```text
B1: ¬¬P → P
B2: P ∨ ¬P
B3: P
B4: ¬P
```

The test asks whether each commitment is:

1. admissible in the regime;
2. a strengthening of the regime rather than a contradiction;
3. actually contradictory with existing commitments;
4. merely unresolved within the regime.

## 4. Observations

### B1 — Double-negation elimination

`B1` is not generally derivable in pure intuitionistic logic. Therefore:

```text
L-I + B1
```

should not automatically be classified as inconsistent.

It is better described provisionally as an **additional classical commitment** (or a commitment with classical strength) whose status must be made explicit.

In `L-C`, the same commitment is available as part of the logical regime and therefore does not represent the same architectural event.

**Important distinction:** failure to derive `B1` intuitionistically is not itself a contradiction.

### B2 — Excluded middle

Likewise:

```text
L-I ⊬ P ∨ ¬P
```

in general.

Thus adding `B2` to an intuitionistic context is not automatically a contradiction. It is a **logical strengthening / classical commitment**.

This supports the distinction:

```text
not derivable in L-I ≠ contradictory in L-I
```

### B3 and B4

`B3: P` and `B4: ¬P` are individually admissible commitments. Their joint status depends on the semantics of the context. When both are simultaneously imposed in an ordinary setting where `¬P` has its standard meaning, they produce a direct incompatibility.

The important point is that the contradiction is generated by the **joint commitments**, not by either Brick's independence or by the logical regime merely being intuitionistic.

## 5. Preliminary classification

| Candidate | L-I | L-C | Provisional architectural interpretation |
|---|---|---|---|
| B1: `¬¬P → P` | Not generally derivable | Available | Classical-strengthening commitment in L-I; ordinary consequence in L-C |
| B2: `P ∨ ¬P` | Not generally derivable | Available | Classical-strengthening commitment in L-I; ordinary consequence in L-C |
| B3: `P` | Admissible | Admissible | Ordinary commitment |
| B4: `¬P` | Admissible | Admissible | Ordinary commitment |
| B3 + B4 | Incompatible under standard reading | Incompatible under standard reading | Genuine conflict |

## 6. Key finding

The probe supports the following distinction:

```text
logical non-derivability
        ≠
contradiction
```

and:

```text
classical strengthening
        ≠
logical inconsistency
```

Therefore a candidate Brick should not be rejected merely because its commitment is not derivable in the current logical regime.

Instead, the system should ask what kind of event occurred:

```text
1. already derivable
2. admissible but not derivable
3. requires explicit logical strengthening
4. contradictory with context
5. unresolved / requires further analysis
```

## 7. Consequence for the trunk policy

This probe strengthens the usefulness of the project's existing intuitionistic-default principle, but does not by itself settle the final policy.

A classical commitment introduced into an intuitionistic context should be distinguishable from a contradiction. It may be a legitimate architectural move in a branch, while a trunk introduction would require the stronger justification already contemplated by the project.

Thus:

```text
classical ≠ invalid
non-intuitionistic ≠ contradiction
not intuitionistically provable ≠ conflict
```

The issue for the trunk is therefore one of **logical commitment and necessity**, not merely consistency.

## 8. Proposed context-sensitive admissibility model

The experiment suggests representing admissibility as a relation involving at least:

```text
Admissible(B, Context, LogicRegime)
```

where `Context` includes established commitments and `LogicRegime` identifies the currently active logical framework.

This is a research model only.

## 9. Open questions

1. What exactly counts as a logical regime in BOMA: object logic only, or also framework/meta-level assumptions?
2. Should a Brick explicitly declare the logical principles it requires?
3. How should a classical-strengthening Brick be represented when introduced into an intuitionistic branch?
4. Can local admissibility be decided without computing global consistency?
5. How should conservative extensions be distinguished from genuinely stronger logical commitments?
6. Does `non-conflict` need to be defined relative to a proof-theoretic notion, a semantic notion, or both?

## 10. Epistemic status

```text
Supported:  non-derivability is not contradiction
Supported:  classical strengthening is not automatically inconsistency
Hypothesis: admissibility is context- and logic-relative
Open:       formal conflict relation
Open:       formal logical-regime representation
Open:       trunk-specific treatment of classical strengthening
```

No normative BOMA rule is established by this probe.
